# Round 19 — Windows checklist

The headless suite proves the logic on every push. These are the things only a real rig shows:
one line per item, what to do, and what you should see. Tick them on a Windows machine with the
full build (libVLC bundled), two displays, an internet connection and an Anthropic API key for
the assistant rows.

| 3 | Attachments: a plan from the material | BUILD → Assistant: ATTACH… a running order in Excel, a brief in Word, a screenshot of a stage plan or a photo of the rig (a 4K one), and a PDF together; press ASK with nothing typed; then APPLY the show plan; try a video file and a 30 MB PDF | Each file becomes a chip with its note (the picture's original size and the size sent, the sheet's rows, the PDF's pages, the words); the ask goes as one turn; the reply says what it read from each file and proposes screens, looks, lower thirds and a cue stack with the running order's times; APPLY lands them (the picture parts in the preview); the video is refused with a line saying what the assistant reads; the PDF is refused as larger than 20 MB; a follow-up question two asks later still knows the running order without the chips coming back |
| 2 | The assistant reads the desk | With two displays joined as one canvas, a look on air, EDIT SAFE open with a different look in the preview, a cue on standby, a capture input mounted with a nickname and the playlist playing: ask the assistant *what is on air right now, and what is in the preview?*, then *add a screen called Main wall* (the name of the canvas), then *put the walk-in look on air* | It answers from the desk — the air's look and the preview's by name, the canvas by its letter and name with both screens, the standby cue, the input by its nickname and never its device string or address, the track playing; it declines to add a screen that already exists and offers to update it; it says a look cannot be put on air by it and tells you to TAKE (its proposal lands in the preview) |
